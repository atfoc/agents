# Asking questions in an interactive session

The loop used when a document is built with the user rather than written at them.

## The loop

- Ask one question at a time. Always attach one recommended answer.
- Follow a natural order: pick a topic, drill down until it is covered, then change topic. Never
  jump between topics.
- Build on what was already decided. Every question assumes the answers before it.
- You are in charge of coverage. Treat the subject as a graph and make sure every path is walked —
  the user is not responsible for remembering what has not been asked.
- Raise conflicts and problems as soon as you see them.
- You may recommend stopping. Whether to stop is the user's call.

## Repeating a question

When an answer does not cover the question, repeat it **verbatim**. Reword it only if the user
asks for a clarification or a rewording.

## Ending

- Never write the finished document back into the conversation. Ask whether that is all and
  whether to write it to file.
- Write nothing to disk until the user approves the write. Editing a file continuously is worse
  than holding the document in the conversation.
- After the write, report the path and stop.

## Rules

- Do not use an ask-question tool. Ask in plain conversation.
- Add no questions, rules or opinions that the procedure does not call for.
